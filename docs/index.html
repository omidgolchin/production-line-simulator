How the verdict is decided simulation, formulas, sources

Bottleneck by simulation. The line is simulated period by period, many times over. In each period, a station counts as limiting when work was waiting in front of it, room was free behind it, and its own capacity that period was the binding limit. A station's limiting share is the fraction of periods it held the line back that way; ties count for nobody. This is the headline test, because the station with the lowest average is not always the station that limits a variable line.

Little's law. Work in process equals throughput times cycle time (Little, 1961). The check compares the simulator's own three counters; a settled line satisfies it closely, and a line whose queues grow all run long does not, which the check reports instead of hiding.

Kingman's approximation. Next to the simulated queue in front of each station, the full numbers show Kingman's heavy-traffic form: queue ≈ (arrival variance + capacity variance) / (2 × (average capacity − throughput)), with arrival variability carried station to station by Whitt's departure rule. In this batch-period model the formula runs high at moderate utilization (by roughly a third to double on the tested lines) and explodes when a station's average capacity sits within a couple of percent of throughput, where the simulated queue is the number to use; the check on the verdict panel says which case this line is.

Release rules. Push releases work on a schedule, whatever the line can absorb. Drum-buffer-rope ties release to the bottleneck: work waiting at or before the bottleneck is held at the rope length, so a unit enters only when the bottleneck takes one (Goldratt & Cox, 1984). CONWIP releases a new unit only when one leaves the line, capping total work in process (Spearman, Woodruff & Hopp, 1990). The comparison sets every rule to the same output and asks what work in process each needs, and what happens when its setting is 20% too high: push's queues then grow all run, a pull rule holds only the extra units it was allowed (Hopp & Spearman, Factory Physics).

From data. The second mode uses the active-period method (Roser, Nakano & Tanaka, 2001): the station that has been active longest without a break is the momentary bottleneck. The experiments behind this tool, including what language models get right and wrong about such lines, are in the research notes.

How the active-period method works

In every period, the momentary bottleneck is the station that has been active longest without a break (Roser, Nakano & Tanaka, 2001). The logic is simple: a station that is starved or blocked keeps having its run reset, while the bottleneck works on, so its unbroken run keeps growing until it is the longest. A station's bottleneck share is the fraction of periods in which it held that spot, with tied periods split evenly.

The method needs a log that shows idle time. A state log (busy, starved, blocked, down) is ideal. An output log works when stations post zeros in the periods they could not run. If every station posts output in every period, no station can be separated from the others from that log alone, and the tool says so rather than guessing.

One caution: the lowest average output does not by itself identify the bottleneck. A station can post low output because it is starved by the station in front of it. The verdict panel compares the two readings and flags it when they point at different stations.

When to use it, and when not assumptions, limits, alternatives

Use it on a serial line (stations in a fixed order, one product or a product family with similar times) to find the constraint, to see what a plan can really get out of the line, or to compare where extra capacity, buffer space or a release rule pays most.

It assumes the following. Each line says what happens to the answer when your case breaks the assumption.

AssumptionIf yours differs
One serial line: every unit visits the stations in the same order.Parallel machines, rework loops or different routings for different products are outside this model. Treat a group of parallel machines as one station with their combined rate, as a first cut.
Each station's output varies around a stable average, described by one variability number (or a die roll).Breakdowns, setups and batching enter only through the average and its spread. Long, rare breakdowns hurt more than the same average loss spread evenly, so the tool can be optimistic for them.
Rates stay the same over the run: no learning, no shifts with different staffing.Model each shift pattern separately, with that shift's rates.
Raw material is always available at the front, and finished units always leave at the end.If the first station waits for supplies, or the end waits for shipping space, those are stations too. Add them.
Time moves in discrete periods; within a period work flows into a buffer before the next station uses it.Choose a period in which your buffer sizes make sense (an hour if buffers hold a few units, a shift if they hold dozens).
Data mode: the log shows idle time.A log in which every station produced something in every period cannot separate the stations, and the tool says so.

Do not use it for job shops where each order follows its own route, for scheduling the sequence of orders on machines, or for lines where the bottleneck changes with the product mix (plan each product separately, or use a job-shop scheduler or a discrete-event package such as SimPy or AnyLogic).

Where this tool comes from the problem and data it was built on, and how it was generalised

The tool comes out of a set of simulation studies on serial production lines, kept in this repository (results/summary.md), starting from the dice game in Goldratt's The Goal. They found:

  • A balanced line still loses output. Five stations rolling dice (average 3.5) deliver 3.27 per period. So the tool reports output from simulation, not from the slowest station's average.
  • Capacity pays only at the bottleneck. Adding 1 at the bottleneck raised output by 0.80; adding it at the first station raised it by 0.00 and piled up 150 more units. The ranked list of changes is this experiment, run on your line.
  • Small buffers starve the line. On a dice line, caps of 10, 4 and 2 units in front of each station cut output to 2.96, 2.23 and 1.55, which is why buffer space is one of the ranked changes.
  • Release rules decide the queue. Push and drum-buffer-rope gave the same output, but push held 384 units in process against 19. So the release rule is an input.

How it was generalised. The studies used fixed lines. The tool takes any serial line (station rates, variability and buffer space), runs the same paired simulations to rank changes on it, and adds a mode that finds the bottleneck from a log of station states. The studies also checked whether language models can find the bottleneck; that part did not become part of the tool, and its AI fill only reads a description into the form.
